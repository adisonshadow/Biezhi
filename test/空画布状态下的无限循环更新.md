根据代码和控制台错误信息，问题在于**空画布状态下的无限循环更新**。主要原因是：

1. **Canvas组件中的useEffect依赖循环**：当workflow.nodes为空数组时，Canvas组件的useEffect被反复触发
2. **WorkflowDesigner的state更新触发重新渲染**，进而导致Canvas重新渲染
3. **依赖项比较逻辑问题**：即使在空画布状态下，某些依赖项的变化也会触发useEffect

## 问题分析

从控制台日志可以看到：
1. 第一次加载工作流时，workflow.nodes为空数组 `[]`
2. Canvas的useEffect触发，检测到是空画布，跳过了setState
3. 但随后Canvas的useEffect再次触发，导致无限循环

主要问题在`Canvas.tsx`的useEffect中，特别是空画布的逻辑处理。

## 解决方案

### 1. 修复Canvas.tsx中的空画布处理逻辑

在`Canvas.tsx`中，修改useEffect的开始部分，添加更严格的空画布检测：

```typescript
// 在 useEffect 开始处添加
React.useEffect(() => {
  // 空画布的提前退出逻辑
  const workflowNodesStr = JSON.stringify(workflow.nodes || []);
  const isEmptyCanvas = workflowNodesStr === '[]';
  const wasEmptyCanvas = lastWorkflowNodesRef.current === '[]';
  
  // 如果当前和上次都是空画布，直接返回，避免任何更新
  if (isEmptyCanvas && wasEmptyCanvas) {
    console.log('[Canvas空画布优化] 当前和上次都是空画布，跳过所有处理');
    // 只更新ref记录，不执行任何setState
    if (hasWorkflowChanged) {
      lastWorkflowNodesRef.current = workflowNodesStr;
      lastWorkflowConnectionsRef.current = JSON.stringify(workflow.connections || []);
    }
    if (hasOperatorsChanged) {
      lastOperatorsStrRef.current = JSON.stringify(operators);
    }
    return;
  }
  
  // ... 原有的逻辑
}, [stableWorkflow, operators.length]);
```

### 2. 修复WorkflowDesigner.tsx中的初始化逻辑

在`WorkflowDesigner.tsx`中，确保初始状态时不会触发不必要的更新：

```typescript
const loadWorkflow = async () => {
```

### 3. 优化Canvas组件的稳定依赖项

在`Canvas.tsx`中，使用更稳定的依赖项：

```typescript
// 修改 stableWorkflow 的定义，使用更稳定的依赖项
const stableWorkflow = React.useMemo(() => workflow, [
```

### 4. 添加防抖机制防止频繁更新

在Canvas组件中添加防抖机制：

```typescript
// 添加防抖引用
const updateTimeoutRef = React.useRef<NodeJS.Timeout | null>(null);

React.useEffect(() => {
  // 清除之前的定时器
  if (updateTimeoutRef.current) {
    clearTimeout(updateTimeoutRef.current);
  }
  
  // 设置防抖定时器
  updateTimeoutRef.current = setTimeout(() => {
    // 原有的 useEffect 逻辑
    const workflowNodesStr = JSON.stringify(workflow.nodes || []);
    const isEmptyCanvas = workflowNodesStr === '[]';
    
    // 空画布特殊处理
    if (isEmptyCanvas && lastWorkflowNodesRef.current === '[]') {
      console.log('[Canvas防抖] 空画布已稳定，跳过处理');
      return;
    }
    
    // ... 原有的逻辑
  }, 100); // 100ms 防抖
  
  return () => {
    if (updateTimeoutRef.current) {
      clearTimeout(updateTimeoutRef.current);
    }
  };
}, [stableWorkflow, operators.length]);
```

### 5. 完整的Canvas.tsx useEffect修复方案

这是最关键的修复，将原有的useEffect逻辑替换为：

```typescript
React.useEffect(() => {
  // 1. 快速空画布检测
  const workflowNodesStr = JSON.stringify(workflow.nodes || []);
  const workflowConnectionsStr = JSON.stringify(workflow.connections || []);
  const operatorsStr = JSON.stringify(operators);
  
  const isEmptyCanvas = workflowNodesStr === '[]';
  const wasEmptyCanvas = lastWorkflowNodesRef.current === '[]';
  
  // 2. 空画布稳定状态：如果当前和上次都是空画布，完全跳过
  if (isEmptyCanvas && wasEmptyCanvas) {
    console.log('[Canvas稳定空画布] 跳过所有处理');
    // 只更新ref，不执行任何setState
    if (workflowNodesStr !== lastWorkflowNodesRef.current) {
      lastWorkflowNodesRef.current = workflowNodesStr;
    }
    if (workflowConnectionsStr !== lastWorkflowConnectionsRef.current) {
      lastWorkflowConnectionsRef.current = workflowConnectionsStr;
    }
    if (operatorsStr !== lastOperatorsStrRef.current) {
      lastOperatorsStrRef.current = operatorsStr;
    }
    return;
  }
  
  // 3. 检查是否有实际变化
  const hasWorkflowChanged = 
    workflowNodesStr !== lastWorkflowNodesRef.current ||
    workflowConnectionsStr !== lastWorkflowConnectionsRef.current;
  const hasOperatorsChanged = operatorsStr !== lastOperatorsStrRef.current;
  
  // 4. 如果没有变化，跳过
  if (!hasWorkflowChanged && !hasOperatorsChanged) {
    return;
  }
  
  console.log('[Canvas更新] 检测到变化，执行更新', {
    hasWorkflowChanged,
    hasOperatorsChanged,
    isEmptyCanvas
  });
  
  // 5. 标记为外部更新，避免触发同步循环
  isExternalUpdateRef.current = true;
  
  // 6. 更新ref记录
  lastWorkflowNodesRef.current = workflowNodesStr;
  lastWorkflowConnectionsRef.current = workflowConnectionsStr;
  lastOperatorsStrRef.current = operatorsStr;
  
  // 7. 空画布的特殊处理
  if (isEmptyCanvas) {
    console.log('[Canvas空画布初始化] 设置空数组');
    // 只在当前节点/边状态不是空时才更新
    const currentNodesEmpty = currentNodesRef.current.length === 0;
    const currentEdgesEmpty = currentEdgesRef.current.length === 0;
    
    if (!currentNodesEmpty) {
      setNodes([]);
    }
    if (!currentEdgesEmpty) {
      setEdges([]);
    }
  } else {
    // 8. 非空画布的正常更新逻辑
    const newNodes: Node[] = (workflow.nodes || []).map((node: WorkflowNode) => {
      // ... 原有的节点创建逻辑
    });
    setNodes(newNodes);
    
    const newEdges: Edge[] = (workflow.connections || []).map((conn: WorkflowConnection) => {
      // ... 原有的边创建逻辑
    });
    setEdges(newEdges);
  }
  
  // 9. 延迟重置外部更新标志
  setTimeout(() => {
    isExternalUpdateRef.current = false;
  }, 200);
}, [stableWorkflow, operators.length]);
```

## 总结

问题的核心是**空画布状态下的React状态更新循环**。通过：

1. **加强空画布检测**：明确识别并处理空画布状态
2. **添加稳定状态检查**：避免在相同状态下重复更新
3. **优化依赖项**：使用更稳定的依赖项减少不必要触发
4. **添加防抖机制**：防止快速连续更新

这些修改应该能解决你的无限更新深度错误。主要修复集中在`Canvas.tsx`文件中的useEffect逻辑，特别是空画布的处理部分。
